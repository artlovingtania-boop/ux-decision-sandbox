# API-план: генерація Top Tasks

Один API/AI-крок MVP: виведення Top Tasks з опису продукту через Gemini.

## Вхід

Надсилається з форми `app.html`, коли поле Top Tasks лишили порожнім
(за замовчуванням — задачі виводяться моделлю, як і описано в ядрі:
«виводяться з аудиторії й цілі, якщо не задані»).

| Поле       | Джерело у формі         | Приклад                                              |
|------------|--------------------------|-------------------------------------------------------|
| category   | Категорія продукту        | «лендінг громадської організації»                    |
| support    | Чим підкріплюється діяльність | «щомісячні звіти про витрачання, реєстр партнерів…»   |
| audience   | Цільова аудиторія (об'єднана) | «донори, які прийшли після допису в соцмережах (головна); …» |
| goal       | Бізнес-ціль                | «разова пожертва або підписка на щомісячну»           |

## Тула

- **Ендпоінт**: `POST /api/top-tasks` (serverless-функція Vercel, `api/top-tasks.js`)
- **Модель**: Gemini, `models/gemini-3.6-flash` (через `generateContent`)
- **Де ключ**: `process.env.GEMINI_API_KEY` — змінна середовища у Vercel
  (Production/Preview/Development), у коді й репозиторії відсутній

## Промпт до моделі

Побудований на формулюванні з ядра: 3–5 задач, формат «дієслово + об'єкт»,
без вигаданих деталей поза аудиторією й ціллю. Модель повертає чистий
JSON (`responseMimeType: 'application/json'`), без markdown-огорожі.

## Поля відповіді

```json
{ "tasks": ["...", "...", "..."] }
```

Якщо `tasks` відсутні, не масив або порожні — функція повертає помилку
502 з описом причини (замість мовчазної порожньої відповіді).

## Обробка помилок

| Ситуація                                | Що бачить користувач                              |
|-------------------------------------------|----------------------------------------------------|
| Немає одного з полів входу                 | 400, «Не вистачає полів»                            |
| Ключ не налаштований на сервері            | 500, «Ключ не налаштований на сервері»              |
| Gemini відповів помилкою (напр. 503 — перевантажений) | 502 з деталями; прогін все одно створюється, без Top Tasks |
| Мережевий збій                             | 500 з описом; прогін все одно створюється            |

## Поведінка в інтерфейсі

Поки триває запит — кнопка «Запустити аналіз» показує «Виводимо
задачі…» і неактивна. Успіх/невдача повідомляються коротким тостом.
Прогін завжди створюється, навіть якщо Gemini не відповів — просто без
Top Tasks (аудит лишається коректним, на один показник менше, це
позначено в самій методиці ядра).

## Що не покриває цей крок

Генерація трьох варіантів структури, осі, аудит (код + персона) —
досі мокові дані, окремий наступний крок.
