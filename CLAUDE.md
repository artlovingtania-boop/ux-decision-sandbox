# UX-Decision Sandbox — лендінг і продукт

## Джерело істини

Макет у Figma. Файл `Jylanp6Ahzf6HERQxK2eG1`, фрейм лендінгу `352:3909`.

Усі значення — розміри, кольори, шрифти, відступи, межі, тексти — беруться з файлу через Figma MCP. **Нічого не вигадуй і не додумуй.** Якщо чогось у файлі немає, скажи про це й зупинись, не підставляй правдоподібне.

Читай через `get_design_context` з `clientLanguages: html,css`. Він віддає точні пікселі, токени й текст. `get_metadata` кешує стан — не покладайся на нього після змін.

Це джерело істини діє тільки для `index.html`. Для `app.html` фрейма в Figma немає — фрейм `352:3909` це лендінг, не екран продукту. У файлі є лише проби екрана продукту в чужих кольорах, не в токенах Sandbox — їх не використовувати ні як джерело значень, ні як референс. Стиль `app.html` береться з наявних CSS-класів `index.html` (`.button`, `.tag`, картки тощо), а не з Figma.

## Стек

Два файли:
- `index.html` — лендінг, CSS усередині, без збірки, без фреймворків, без npm, без JS.
- `app.html` — екран продукту. Теж без збірки й фреймворків, але тут дозволений JS: форма з робочою логікою, збереження в `localStorage`.

Шрифти — DM Sans (400, 700, 900) і DM Mono (400) з Google Fonts.
Ассети — у папці `assets/`, завантажені через `download_assets`.

## Плани

Стилі елементів форми в `app.html` — тимчасові. Після завершення роботи над логікою (API, авторизація, база даних) вони будуть замінені на дизайн-систему Shoelace з накладеними токенами Sandbox. Тому вже зараз:

- не вкладай зайвого в CSS елементів форми — інпутів, кнопок, селектів, повідомлень
- не додавай нових класів-модифікаторів до `.field`, `.button`, `.notice`, якщо без них можна обійтись
- логіку тримай окремо від розмітки: код, що читає значення полів, має працювати незалежно від того, `<input>` це чи `<sl-input>`

Лендінгу `index.html` це не стосується — він лишається на своєму CSS.

## Розкладка

Контейнер `max-width: 1200px` по центру, фон на всю ширину вікна.
Тільки CSS Grid і Flexbox. Жодного `position: absolute` для розкладки блоків.
**Мобільної версії немає.** Жодних медіазапитів.

## Токени

Токени (`:root` з кольорами, шрифтами, відступами) фізично лежать у `<style>` всередині `index.html`, і `app.html` як окремий файл їх не бачить. Спільність токенів забезпечується так: `app.html` містить копію блоку `:root` з `index.html`. Значення не змінюються, нові не вигадуються — тільки те, що вже є в лендінгу.

Винесення токенів в окремий `tokens.css` — можлива дія на майбутнє, зараз не робимо.

## Заборони

Спільні — стосуються і `index.html`, і `app.html`:

- Не міняй, не переписуй і не скорочуй тексти з макета
- Не додавай секцій, блоків чи елементів, яких немає у фреймі (для `app.html` — яких немає в узгодженому плані екрана)
- Не вигадуй іконок — завантажуй з файлу
- Не малюй ілюстрації кодом — вони приходять картинками

Тільки для `index.html` (лендінг):

- Не роби логін, реєстрацію, збір даних, аналітику
- Не додавай анімацій, паралаксу, ефектів появи при скролі
- Форми нічого не надсилають, посилання ведуть на `#`

Дозволено в `app.html` (екран продукту) — виняток із заборон лендінгу:

- Форма з робочою логікою і JS дозволені
- Збереження стану — лише в `localStorage`, без мережевих запитів і без бекенду, крім винятку нижче
- Email/password авторизація через Firebase Auth дозволена. Заборона логіну/реєстрації з розділу «Заборони» на `app.html` більше не діє — тільки на `index.html`, там лишається без змін
- Аналітику це не дозволяє — вона й тут поза межами. Логін і реєстрація — тільки через Firebase Auth, як у пункті вище, і ніяк інакше

Виняток: Top Tasks можуть виводитись через серверну функцію `/api/top-tasks` (ключ моделі лишається на сервері, у код `app.html` не потрапляє). Інших мережевих запитів це не дозволяє.
