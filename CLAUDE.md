# UX-Decision Sandbox — лендінг

## Джерело істини

Макет у Figma. Файл `Jylanp6Ahzf6HERQxK2eG1`, фрейм лендінгу `352:3909`.

Усі значення — розміри, кольори, шрифти, відступи, межі, тексти — беруться з файлу через Figma MCP. **Нічого не вигадуй і не додумуй.** Якщо чогось у файлі немає, скажи про це й зупинись, не підставляй правдоподібне.

Читай через `get_design_context` з `clientLanguages: html,css`. Він віддає точні пікселі, токени й текст. `get_metadata` кешує стан — не покладайся на нього після змін.

## Стек

Один файл `index.html`, CSS усередині, без збірки, без фреймворків, без npm.
Шрифти — DM Sans (400, 700, 900) і DM Mono (400) з Google Fonts.
Ассети — у папці `assets/`, завантажені через `download_assets`.

## Розкладка

Контейнер `max-width: 1200px` по центру, фон на всю ширину вікна.
Тільки CSS Grid і Flexbox. Жодного `position: absolute` для розкладки блоків.
**Мобільної версії немає.** Жодних медіазапитів.

## Заборони

- Не міняй, не переписуй і не скорочуй тексти з макета
- Не додавай секцій, блоків чи елементів, яких немає у фреймі
- Не вигадуй іконок — завантажуй з файлу
- Не малюй ілюстрації кодом — вони приходять картинками
- Не роби логін, реєстрацію, збір даних, аналітику
- Не додавай анімацій, паралаксу, ефектів появи при скролі
- Форми нічого не надсилають, посилання ведуть на `#`

## Порядок роботи

Перед кожною зміною опиши план словами — які секції зачіпаєш і що саме робиш — і дочекайся погодження. Код пиши тільки після нього.

Одна секція за раз. Не переходь до наступної, поки я не підтвердила поточну.
